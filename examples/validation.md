## 独立したシナリオ評価

Skill作成前と作成後に、別エージェントが次の6ケースを評価しました。実アプリ操作を伴わない手順シミュレーションです。

| ケース | Skillありの選択 |
| --- | --- |
| dirty checkout、共通祖先とmain先端が異なる | dirty状態を保存し、共通祖先/PR headを別worktreeで比較 |
| 新規画面でBeforeが404 | ルートの不存在をコードで確認しabsent。404を比較画像にしない |
| Safari指定、Chrome/WebKitのみ利用可能 | Safari未確認。WebKitをSafariと表示しない |
| 共通部品と認証が必要な画面 | 公開/到達可能な状態を先行し、残りを未確認として報告 |
| 自分のコメントは2ページ目、他人のmarker、head更新 | 再撮影し、全ページから所有者一致のコメントだけ更新 |
| ローカル画像完成、アップローダーなし | ローカル成果物を残し、PR掲載だけ未完了と報告 |

Skillなしの評価では、新規画面の404をBeforeとして並べる提案がありました。Skillありでは不存在の明記へ変わりました。他の5ケースはSkillなしでも重大な逸脱を観測していません。少数のシミュレーションであり、あらゆるAI/環境での成功を示すものではありません。

独立コードレビューで、別viewportの投稿が既存内容を上書きする問題と、数値文字参照のエスケープ順序の問題を発見しました。再現するテストが失敗することを確認してから修正しました。ローカルのみの依頼でも終了処理へ進むよう手順も明確化しました。

## ローカル撮影の再現

```bash
python3 tests/smoke_server.py
```

表示された2つのURLを実Chromeで開き、それぞれ「通知設定を編集」を押して同じ状態を撮影します。サーバーを終えるときはCtrl-Cを使います。自分が作ったサーバーと一時worktreeを終了処理します。再実行では `examples/smoke/run.json` が新しいSHA/portになるため、撮り直した画像とreportも一緒に更新してください。
